# 목표

**실제 게임(OpenRCT2)을 심판으로 쓰는 "닫힌 회로 우선 + 구간 편집" 탐색기를 만든다. 24×24 타일 영역 안에서 가장 단순한 타원 루프로 시작해, 흥미도(E) "Very High" 등급 코스터를 사람 손 없이 설계해 낸다.**

설계 근거: [OpenRCT2 코스터 설계: 하나씩 지어보기 vs 생성+심판](https://claude.ai/artifact/8ybd2vsZAVMDbqQ6NLTuwP)의 "추천" 절 1~3단계.

## 완료 기준 (전부 충족해야 완료)

| # | 기준 | 판정 방법 |
| --- | --- | --- |
| G1 | 게임 심판 하네스: 조각 목록을 주면 게임이 짓고, 시험 운행하고, 레이팅을 돌려준다. 같은 입력이면 같은 출력이 나오고, 병렬 처리량은 초당 1회 이상이다. | 같은 트랙 반복 평가, 처리량 측정 |
| G2 | 구간 편집이 회로를 항상 닫힌 상태로 유지한다. | 기하 모델이 닫혔다고 판정한 후보 중 게임이 "회로 미완성"으로 거부한 비율이 0% |
| G3 | 결과 코스터가 E ≥ 7.68 (Very High), 강도(I) < 7.68 (High 이하), 멀미도(N) < 5.12 (Medium 이하)를 만족하고 24×24 영역 안에 있다. | 최종 트랙을 새 게임 인스턴스에서 다시 평가 |
| G4 | 모든 시도를 (편집 전 트랙, 편집, 편집 후 레이팅) 형태로 빠짐없이 기록한다. | `runs/*/evals.jsonl` 레코드 수 = 평가 횟수 |
| G5 | 결과물을 남긴다: 최고 코스터 공원 파일, 스크린샷, 결과 보고. | `results/` 파일 |

등급 경계는 OpenRCT2의 레이팅 이름 구간(2.56 간격)을 따른다: Low < 2.56 ≤ Medium < 5.12 ≤ High < 7.68 ≤ Very High < 10.24.

## 확장 목표 (완료 기준 충족 뒤)

- **S1 빠른 심판**: 기록된 데이터로 레이팅 예측 모델을 학습해 홀드아웃 Spearman ρ를 잰다. 앞단 필터로 붙였을 때 같은 게임 평가 예산으로 더 좋은 결과가 나오는지 확인한다.
- **S2 장애물 영역**: 지형 굴곡과 나무가 있는 영역에서도 같은 기준을 달성한다.

# 2단계 목표: 범용 알고리즘 (2026-10-19 18:58 설정)

**공원 맵과 영역만 입력받아, 조건별로 사람이 손대지 않고 흥미도 Very High 코스터를 설계하는 알고리즘을 만든다. 성능은 개발에 쓰지 않은 조건에서 잰다.**

계기: 사용자 요청("테스트한 조건에서만 유효한 것 아닌가? 다양한 조건에 적용할 수 있는 범용 알고리즘을 원한다").

1단계 결과에서 조건별로 사람이 정해 준 부분은 다음과 같다.
- 영역은 직사각형이고, 역의 위치와 방향은 손으로 정했다.
- 시작 타원은 평평한 가장자리를 가정했고, 언덕 높이는 조건마다 골랐다(16×16은 4).
- 지형 정보는 게임에서 읽지 않고, 내가 만든 명세에서 가져왔다.
- 차종은 레이팅 코드를 읽고 내가 골랐다.
- 점수 설정(강도 상한, slack, 일정)은 실패를 보고 고쳤다.

## 완료 기준

| # | 기준 | 판정 방법 |
| --- | --- | --- |
| P1 | **입력 일반화**: 입력은 공원 파일과 영역(타일 집합, 모양 무관)뿐이다. 지면 높이와 경사, 물, 나무와 경치, 길, 다른 탈것은 게임에서 읽는다. | 실제 시나리오 맵에서 사람이 쓴 명세 없이 실행 |
| P2 | **자동 초기화**: 영역 안에서 역의 위치와 방향, 닫힌 시작 회로를 스스로 찾는다. 조건별 매개변수가 없다. | 모든 벤치마크 조건에서 시작 회로를 찾고 게임이 레이팅함 |
| P3 | **고정 설정**: 차종 후보, 탐색 매개변수를 포함한 설정 하나를 모든 조건에 쓴다. 설정은 개발 조건으로만 정한다. | 벤치마크 실행 기록의 설정이 모두 같음 |
| P4 | **보류 검증**: 고정 설정으로 개발에 쓰지 않은 조건에서 돌린다. 조건마다 같은 시간 예산(15분)을 준다. 조건은 두 묶음이다. (a) 새 시드의 무작위 지형 10개, (b) 실제 RCT2 시나리오 맵에서 정해진 절차로 고른 영역 10개. **목표 충족률 80% 이상**이고, 모든 조건에서 닫히고 시험 운행된 코스터가 나와야 한다. | `results/benchmark.json`의 조건별 성패와 E/I/N |

범위: 돈, 토지 소유, 연구 제약은 1단계처럼 끈다(샌드박스). 영역 안의 기존 경치는 지우지 않는다.

진행 규칙은 1단계와 같다. 개발 조건과 보류 조건은 섞지 않는다. 보류 조건은 선정 절차를 먼저 코드로 고정한 뒤에 뽑는다.
